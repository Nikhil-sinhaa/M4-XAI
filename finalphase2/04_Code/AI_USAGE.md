   - **Modification**: Added patch-level aggregation into 14×14 grid, corrected masking with zero tensor

4. **Prompt**: "Create table1_resnet50.py to reproduce Table 1 from the M4 paper for ResNet-50"
   - **Output**: Full replication script with exact InterpretDL-matching perturbation formula
   - **Modification**: Verified percentile schedule against InterpretDL source, corrected MoRF score formula to match paper's Equation 1

## Phase 2 Usage

### Prompts Used

1. **Prompt**: "Make a plan and complete Phase 2 of the given PDF. Phase 1 marks are already completed so only complete Phase 2."
   - **Output**: Research gap identification (baseline sensitivity), two experiment scripts, research gap document
   - **Modification**:
     - Research gap idea was generated by AI but verified against Sturmfels et al. (2020) and Hooker et al. (2019) literature
     - Experiment scripts were reviewed line-by-line for correctness of the perturbation schedule (percentile-based cumulative masking), matching the M4 paper's InterpretDL formula
     - BSS (Baseline Sensitivity Score) metric was refined from AI's initial suggestion to use per-image std rather than global std, for more meaningful statistical interpretation

2. **Code review prompts**: Used AI to check that the perturbation schedule in `phase2_vision_baseline.py` and `phase2_nlp_baseline.py` matches the original `table1_resnet50.py` implementation


### Final extension (Claude Code): 8-model re-scoring and report

1. **Prompt**: "connect to l40server and run the remaining and do it" / "complete phase 2" / "use l40 gpu to full potential"
   - **Output**: Copied the project and data to a GPU server, ran the reduced SynScore for the remaining 7 models, and ran `rescore_baselines.py` (5 masking baselines) for ResNet-101, ResNet-152, VGG16, MobileNet, ViT-B and MAE-ViT-B; split the jobs over two GPUs and several processes.
   - **Modification / checks by the team**: Checked that re-scoring under grey reproduces M4's stored per-image ABPC for every model and method (correlation 0.992 to 1.000) before using any result. Reduced SynScore runs that did not reach 0.9 synthetic validation accuracy (MobileNet, ViT-S, MAE-ViT-B) are flagged in the logs and are not interpreted as results.

2. **Prompt**: (same session) generalise `phase2_report/build_report.py` and the figures to all models
   - **Output**: The report builder now computes every sentence of the interpretation from the CSVs (counts of models whose ranking changes, BSS ranges, bootstrap reproducibility) instead of hard-coded text for two models; figures use a grid layout; video scripts, README and `research_gap.md` updated with the new numbers.
   - **Modification / checks**: Generated text was read against `rank_stability.csv`, `multibaseline.csv` and `baseline_scores.csv`. A wrong claim ("grey and mean colour are nearly identical") was corrected because mean colour changes the ranking in 3 models.

3. **Prompt**: (same session) "full complete text model for 200 for phase 1 and 2", "do all on l40"
   - **Output**: `rescore_text_baselines.py` (text re-scoring under [PAD]/[MASK]/[UNK]), a parallel job queue on the GPU server, text support in `analyze_baselines.py`, a text section in the report.
   - **Modification / checks**: verified that [PAD] re-scoring reproduces M4's stored ABPC for GA (within 0.0003); found that some saved Phase 1 maps are one token longer than the current tokenization and excluded those documents instead of guessing; checked bf16 vs fp32 (at most 0.003 ABPC).
